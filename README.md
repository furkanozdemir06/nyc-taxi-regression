# 🚕 NYC Taxi Trip Duration Prediction

Predicting how long a New York City taxi trip will take from pickup and dropoff locations, time of day, and trip distance. Accurate duration estimates support better travel time prediction, fleet planning, and passenger experience.

## Highlights

- Large-scale regression on 1.4 million NYC taxi trips (2016)
- Careful data cleaning of durations, GPS coordinates, passenger counts, and distances
- Geographic feature engineering: haversine distance, Manhattan-style distance, and travel direction
- Benchmark of 10 regression algorithms; **XGBoost performed best with R² ≈ 0.79**
- Feature importance analysis and a saved model ready for reuse

## Dataset

The data follows the NYC Taxi Trip Duration format (`train.csv` and `test.csv`).

| Column | Description |
|--------|-------------|
| `id` | Trip identifier |
| `vendor_id` | Taxi provider |
| `pickup_datetime`, `dropoff_datetime` | Trip start and end timestamps |
| `passenger_count` | Number of passengers |
| `pickup_longitude`, `pickup_latitude` | Pickup coordinates |
| `dropoff_longitude`, `dropoff_latitude` | Dropoff coordinates |
| `store_and_fwd_flag` | Whether the trip record was held in the vehicle before sending |
| `trip_duration` | **Target:** trip duration in seconds (train only) |

The training file has 1,458,644 trips and no missing values.

## Approach

1. **Exploratory data analysis**
   - Examined the log-transformed duration distribution, passenger and vendor counts, pickup and dropoff maps, duration by hour of day, and a correlation heatmap.
2. **Data cleaning** (1,458,644 to 1,295,086 trips)
   - Kept trips lasting between 60 and 7,200 seconds.
   - Kept pickups and dropoffs inside the New York City area.
   - Kept passenger counts from 1 to 6.
   - Kept trip distances between 0.1 and 50 km.
   - Removed duration outliers with the IQR rule, leaving trips of 60 to 2,074 seconds.
3. **Feature engineering**
   - Time features: `pickup_hour`, `pickup_day`, `pickup_weekday`, `pickup_month`, `is_weekend`.
   - Distance features: `distance_km` (haversine) and `manhattan_km`.
   - `direction`: bearing from pickup to dropoff.
   - Encoded `vendor_id` and `store_and_fwd_flag`.
4. **Modeling**
   - Applied `log1p` to the target, scaled features with `MinMaxScaler`, and used an 80/20 train/validation split.
   - Compared 10 regression algorithms.
5. **Interpretation and export**
   - Retrained XGBoost on the full training data, plotted the top 10 feature importances, and saved the model with `joblib`.

## Results

Validation results on the log-transformed target (RMSE on the log scale corresponds to RMSLE):

| Model | R² | RMSE | MAE |
|-------|-----|------|-----|
| **XGBoost** | **0.7906** | **0.2992** | **0.2235** |
| Extra Trees | 0.7861 | 0.3024 | 0.2255 |
| Gradient Boosting | 0.7265 | 0.3420 | 0.2613 |
| Decision Tree | 0.5608 | 0.4333 | 0.3230 |
| K-Neighbors | 0.5509 | 0.4381 | 0.3330 |
| Ridge | 0.4033 | 0.5051 | 0.3941 |
| Linear Regression | 0.4033 | 0.5051 | 0.3941 |
| SGD Regressor | 0.4024 | 0.5054 | 0.3953 |
| Lasso | -0.0000 | 0.6538 | 0.5302 |
| ElasticNet | -0.0000 | 0.6538 | 0.5302 |

Tree-based ensembles clearly outperformed linear models, which suggests that trip duration depends on non-linear relationships between distance, location, and time. Trip distance and location coordinates appear to be the main drivers of duration.

The model is trained on trips between 1 and about 35 minutes, so it is best suited to typical trip lengths.

## Getting Started

```bash
git clone <your-repo-url>
cd <your-repo-folder>
pip install pandas numpy scikit-learn xgboost matplotlib seaborn joblib
```

Place `train.csv` and `test.csv` in the project root, then run:

```bash
jupyter notebook NYTaxi.ipynb
```

The notebook saves the trained model as `nyc_taxi_xgb_model.pkl`.
